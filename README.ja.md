# Local Tags

[English](README.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | [Deutsch](README.de.md)

Local Tagsは、Obsidianにファイル内だけで有効な `##tags` を追加します。異なるノートで同じタグ名を使っても、補完候補やタグ一覧が混ざりません。

公開済みの配布物は [Releases](https://github.com/mstksb/obsidian-local-tags/releases) で確認できます。Obsidianの **Settings → Community plugins → Browse** から **Local Tags** を検索してインストールすることもできます。

## 主な機能

- `##project` のようなタグや、`##people/Alex` のような階層タグを記述できます。
- 現在のMarkdownファイルにあるタグ名を補完します。
- ノートごとのタグの概要を補完候補の横や、本文・タグパネルのツールチップに表示します。
- 補完の部分一致・前方一致と、大文字・小文字を区別するかを選べます。
- Source mode、Live Preview、Reading Viewでタグを表示します。
- 現在のファイルのタグを階層パネルで確認し、名前や概要ですぐに絞り込めます。
- パネルのタグをクリックして、現在のファイル内でその文字列を検索できます。
- タグをShift+クリックすると、行のハイライトと一致したタグの枠を表示しながら、本文内の出現箇所を順に巡回できます。
- プラグイン設定で共通の文字色・背景色・強調・上下の余白を調整できます。
- ノートごとの文字色・背景色・枠線色・太字・下線・斜体を `local-tags-config` に保存し、親タグから子タグへ継承できます。
- タグパネルから、不足する設定の追加、空の設定の除去、ビビッドな補色の生成、定義のソート、設定のタグ見出しまでの展開を行えます。
- Source modeとLive Previewでは、設定内のカラースウォッチから色を編集し、設定エラーをパネルで確認できます。
- Reading Viewと、Live Previewで編集中ではないタグでは、必要に応じて `##` を非表示にできます。

## 操作例

補完・階層タグ一覧・クリックによる検索は、通常のタグに近い操作で使えます。Local Tagsでは、ノートごとにタグを独立させ、ノートごとのランダム装飾やShift+クリックによる巡回も利用できます。

### 入力しながらタグ一覧を絞り込む

**Search tags** に入力すると、現在のノートのタグ一覧がすぐに絞り込まれます。**Tag name** と **Summary** のチェックボックスで、名前・概要・両方から検索対象を選べます。大文字・小文字を区別せずに照合し、一致したタグの親タグも表示します。検索文字列を消すと一覧全体に戻ります。詳細は[タグパネル内の検索](docs/usage.ja.md#tag-panel-search)を参照してください。

![タグパネルで検索文字列を入力し、タグ名と概要の検索対象を切り替える](assets/demos/tag-panel-search.gif)

### 入力中にタグを補完する

`##` を入力して候補を絞り、Enterでタグを挿入します。候補は現在のMarkdownファイルから取得します。部分一致では、`##rev` に対して `##launch/review` が見つかります。

![タグ名の一部を入力して補完候補を選び、完全なタグ名を挿入する](assets/demos/completion.gif)

### ノートごとにタグを独立させる

Launch planからGarden planへ切り替えると、補完候補とタグパネルの両方が現在のノートに追従します。標準の `#tags` はVault全体で索引化されますが、ローカルの `##tags` はファイルごとに独立したタグを持ちます。

![ノートを切り替えるとローカルタグ一覧と補完候補が変わる](assets/demos/file-local-tags.gif)

### タグの意味をその場で確認する

`local-tags-config` 内で、タグ宣言と同じ行の後ろに短い概要を追加します。概要は補完候補の横と、本文やタグパネルのタグにポインターを合わせたときに表示されます。Enterで挿入されるのはタグ名だけです。書式は[タグの概要](docs/usage.ja.md#tag-descriptions)を参照してください。

![補完候補と、本文・タグパネルのツールチップにタグの概要を表示する](assets/demos/tag-summaries.gif)

### ワンクリックで配色する

**Random decoration** を選ぶと、現在のノートのタグにビビッドな補色を生成します。デモではLive Previewを使っています。装飾設定はノートの `local-tags-config` セクションに保存されます。

![ランダム装飾で本文とタグパネルのタグの色が変わる](assets/demos/random-decoration.gif)

### Shift+クリックで出現箇所を巡回する

Shiftを押しながらパネルのタグをクリックすると、現在のノート内の出現箇所へ移動します。対象行のハイライトと一致したタグの枠で、現在位置を示します。

![タグをShift+クリックして、ハイライトされた3か所を順に巡回する](assets/demos/shift-click-navigation.gif)

### クリックでObsidianの検索を開く

パネルのタグをクリックすると、現在のファイルとタグ文字列を入力した状態で、Obsidian標準の検索ペインが開きます。検索結果はそのノート内に限定されます。

![タグをクリックすると、現在のノートに限定した結果を標準の検索ペインに表示する](assets/demos/click-search.gif)

## 動作環境

デスクトップ版Obsidian `1.14.4` 以降が必要です。Local Tagsはデスクトップ専用のプラグインです。

## インストール

ローカルでビルドしたものを使う場合は、`dist/local-tags/` にある `main.js`、`manifest.json`、`styles.css`、`LICENSE`、`THIRD-PARTY-NOTICES.txt` を `<vault>/.obsidian/plugins/local-tags/` に配置し、Obsidianのコミュニティプラグイン設定で **Local Tags** を有効にしてください。

インストール済みのビルドを置き換えた場合は、プラグインを無効にしてから再度有効にしてください。新しく配置したプラグインが一覧に表示されない場合は、Vaultを開き直してください。

## はじめに

1. Markdownノートに `##project` や `##people/Alex` を追加します。
2. `##` と既存のタグ名の一部を入力して候補を選び、Enterで確定します。Escでキャンセルできます。
3. **Open tag panel** コマンドでタグパネルを開きます。
4. パネルのタグをクリックすると現在のファイル内を検索し、Shift+クリックすると本文内で一致するタグを順に巡回します。
5. **Settings → Local Tags** を開いてタグの外観を調整します。
6. ノートごとの装飾を使う場合は、パネルの **Settings, actions and messages** を展開し、**Add missing settings** を選びます。生成された設定に値を入力するか、**Random decoration** で色を生成します。

ローカルタグは `##` を使い、Obsidian標準の `#tags` とは別に扱われます。

入力規則・認識範囲・共通の外観設定・ノートごとの装飾・タグの概要・パネル操作・本文内巡回・検索上の注意点は、[利用ガイド](docs/usage.ja.md)を参照してください。

## 制限事項

英語・日本語のテキストで基本操作が動作することを想定していますが、包括的な検証は行っていません。ほかの言語での動作は未検証です。

READMEと利用ガイドは7言語版を用意しています。資料の翻訳によってプラグインUIの対応言語が変わることはなく、各言語でのタグ認識や入力メソッドの動作を検証済みとするものでもありません。

## ビルドとテスト

Node.js 24とnpmを使います。

```sh
npm ci --ignore-scripts
npm run check
```

配布用ビルドは `dist/local-tags/` に出力されます。個別の確認コマンドやリリース手順は[開発ガイド](docs/development.md)を参照してください。

## プロジェクトの方針

このプロジェクトはプルリクエストを受け付けていません。バグ報告はGitHub Issuesで受け付け、ベストエフォートで対応します。機能要望も投稿できますが、優先度は非常に低いものとします。継続的な保守・サポート・機能追加は保証しません。
